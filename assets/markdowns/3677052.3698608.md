# Abstract

Traditional language models in NLP require a considerable amount of labeled examples,which is notalwaysavailable in data-limited domains like banking. Large Language Models (LLMs) are known to perform effectively with few-shot learning in various domains with just 1-5 examples per class.However, the use of open-source instruction-tuned LLMs,and how they compare to closed-source LLMs and modern few-shot learning approaches like contrastive learning in data-constrained use-cases has been under-explored. Additionally, the understanding of performance-cost trade-offs of these methods,as well as the consideration of infrastructure resource-limited settings through optimal usage of smaller versions of LLMs (7B-9B parameters),a critical concern for budget-limited organizations,has not been studied comprehensively. Our work addresses these gaps by studying the aforementioned approaches over the Banking77 financial intent detection dataset, including the evaluation and comparison of cutting-edge LLMs by Meta, Google,Mistral-AI, OpenAI,and Anthropic in a comprehensive set of few-shot scenarios which include examples selected by a human-expert,as well as with a cost-effective querying method based on retrieval-augmented generation (RAG).We observed that smaller open-source LLMs are able to out-perform larger closedsource ones with effective prompts and RAG.Moreover, they offer a significantly better performance-cost ratio than their larger closedsource counterparts.We also experiment with data-augmentation byusing LLMs to generate artificial labeled examples,which is able to improve performance slightly in a data-scarce scenario.Finally, we explored benefits of fine-tuning using three parameter efficient methods and propose BAI-Fintent,an LLM based on fine-tuned Mistral-7B, that out-performs all other approaches at customer banking intent identification.

# 1 Introduction

The field of Natural Language Processing has seen huge advances, especially in problems like the text classification task,where the objective is to classify a particular text into one of the pre-defined classes.Traditionally for such tasks,full-data classifiers like BERT have been extensively made use of.However, business use cases, particularly in domains like finance [5],suffer from scarcity of data because of challenges such as the comprehensive costs or efforts involved in manual labelling, privacy regulations restricting data access,and even lack of diversity in data due to the complexities in integrating data from disparate sources or teams.Because of these, modern few-shot learning approaches like contrastive learning [24] or in-context learning (through Large Language Models) have gained significant advantage over full-data classifiers in recent times.Previous research has shown that approaches like contrastive learning can help achieve significant performance in tasks like text classification,with just 10 to 20 examples per class.Additionally, using in-context learning by prompting LLMs (like GPT-4) has shown to achieve the same level of performance with just 1 to 3 examples per class [19].However, the use of open-source LLMs (which are Instruction-tuned) and their comparison to closed-source LLMs,and modern few-shot learning approaches like contrastive learning,especially in data-constrained domains like finance, has been under-explored.Additionally,another dimension that has not been studied is the presence of infrastructure resource-limited settings in banks,where the use of smaller versions of LLMs (with parameter sizes of 7B-9B) might make more sense in practical usage.

In the banking domain,BANKING77[5] isa well-established real-life financial intent dataset which provides a very fine-grained set of intents for customer service queries.This is a reasonably challenging task for few-shot learning approaches because of the presence of a large number of classes (77 classes),which have overlapping semantic interpretations.In this paper,we bridge the aforementioned gap by evaluating few-shot learning techniques and cutting-edge LLMs like Llama-3,Mistral, Gemma-2,and Falcon for multi-class intent classification over this dataset.

Therefore,we perform analyses and evaluations in the following four different approaches.Firstly,we make use of in-context learning on smaller versions of the state-of-the-art open-source Instruction-tuned LLMs - Llama, Mistral, Gemma,and Falcon, to evaluate their performance on zero-shot and few-shot (1 and 3 examples perclass) learning.Few shotlearningis explored from two different perspectives -one,where the examples are chosen randomly for each class.And two,where the examples that are best representative of the respective class have been pre-selected by a human expert.

Secondly,we simulate a data-limited scenario where only one example per class is available and investigate the performance and effectiveness of LLM-generated artificial examples on in-context learning.

Thirdly,we further extended the analyses using a RetrievalAugmented Generation (RAG) based approach,where representative examples are significantly reduced to a tiny set of similar examples (up to $2 . 2 \%$ of examples in the classic few-shot setting), which are relevant for each inference classification.We also perform an ablation study,in which we investigate the biasness in this approach.

Overall, we show that using in-context learning with RAG on smaller open-source LLMs can outperform larger closed-source LLMs on financial few-shot text classification tasks,even when presented with fewer examples. Apart from studying performance, we also present a cost analysis on employing these LLMs,where we observed that open-source LLMs (in particular,Mistral-7B) outperforms the most competitive closed-source LLM (GPT-4) by 5 points while costing 540 times less in the context of the test set (3k examples).This could enable small organizations to leverage LLMs without incurring substantial expenses.

Fourthly,we experiment with three Parameter-Efficient FineTuning (PEFT) methods - QLoRA,rsLORA and DoRA to investigate the performance gains with fine-tuning and effciency-performance trade-offs of different methods.Finally,we propose BAI-Fintent,an LLM based on fine-tuned Mistral-7B,that can be used as a stateof-the-art model for customer banking intent identification. We show that this model is able to outperform all other approaches, including in-context learning and RAG-based larger closed-source models at the task,while costing a smallfraction of the cost.Finally, we perform extensive error analysis of the best-performing models.

# 2Related Work

# 2.1 Banking77 Dataset

Banking77 dataset was introduced by Casanueva et al.. On finetuning the BERT[8] model on the full dataset, they were able to achieve an accuracy of $9 3 . 6 6 \%$ .On 10-shot and 30-shot setings, they achieved the best accuracy of $8 5 . 1 9 \%$ and $9 0 . 5 7 \%$ using dual sentence encoders - Universal Sentence Encoder (USE) [6] and ConveRT.

In a later work,Ying and Thomas [26] identified up to 1428 potential label errors in the dataset.They first used a Confidence Learning approach to identify noisy utterances within the same label. Then, they used a cosine similarity based methodology to identify utterances that were semantically identical but were assigned different labels.As aresult,they created a "trimmed dataset", which had no utterances with potential label errors.This yielded a performance increase by $4 . 5 \%$ over the original dataset, resulting in $9 2 . 4 \%$ accuracy and $9 2 . 0 \%$ F1 score.

As fine-tuning the entire model can sometimes lead to distorted pre-trained features,Li et al. augmented the pre-training architecture with prefix tuning plus tuning the last transformer layer to extract intent representations.Using this,they were able to achieve an accuracy of $8 2 . 7 6 \%$ and a Macro-F1 score of $8 7 . 3 \%$ on the Banking77 dataset.

Most recently, Loukas et al. leveraged in-context learning in closed-source LLMs like GPT-3.5,GPT-4,Cohere's Command-nightly, and Anthropic's Claude-2 for intent classification on the dataset. Using representative examples for each class selected bya hired human expert, they were able to achieve $8 3 . 1 \%$ micro-F1 with GPT-4 for 3-shot learning and $8 0 . 4 \%$ micro-F1 for 1-shot learning.Additionally, they also experimented with a RAG methodology, where representative examples are reduced to a set of small but relevant examples depending on their similarity to the test sentence during inference calls.Using this,they were able to achieve a significant boost in performance,with Micro-F1 being $8 7 . 7 \%$ for GPT-4 when 20 most similar examples were chosen for RAG.

# 2.2Few-shot Classification

In real-world use cases like banking,there are several challenges that make it diffcult to have a comprehensive dataset for a task,as mentioned before.In such cases,the following different approaches have been experimented with:

· Fine-tuning:Fine-tuning LLMs often doesn't result in a significant performance gain in a limited-data setting [9]. Also, it becomes computationally more expensive as larger language models are selected.   
· In-context learning: In-context learning [4] is an approach where prompts are given to an LLM,which includes context and instructions of the task and can also include some examples to aid it in that particular task.However, coming up with a prompt that is able to state the task in an appropriate way is challenging and often might result in dubious results.This is because the language models might not havelearned that specific fine-grained task during their training and hence might not be able to understand the meaning of prompt instruction [25].   
· Instruction-tuning:Along with their conversational chat versions,several LLMs have been fine-tuned to follow human instructions,which are called Instruction-tuned LLMs [21] (like Mistral-7B-Instruct, Llama-3-8B-Instruct).However, this too has challenges -it has been observed that in-context learning in instruction-tuned LLMs is correlated with statistical distributions of terms encountered during pre-training [22].Additionally, instruction-tuned LLMs are fine-tuned using instructions from multiple human annotators,which can induce bias.   
·Prompt-tuning:To overcome these challenges,prompt-tunir has emerged as a promising research direction [14].

# 3 Task and Dataset

In customer-oriented conversational systems,intent detection is a well-established problem.Here,a customer's intent（with respect to the issue they are facing or a query they have) in a conversation is to be classified into some pre-defined categories,making it a text classification problem.It is particularly challenging in domains like banking due to the lack of comprehensive datasets,the large number of possible categories,and the semantic overlap between them.

However, existing datasets do not capture these challenges, either due to the presence of a small number of classes $( < 1 0 )$ ,which does not represent the true environment of relevant domains like banking,or the datasets are multi-domain [13],where the set of examples might not capture the full complexity of the domain [3]. Therefore,PolyAI released the Banking77 single domain dataset [5],which provides a very fine-grained set of intents in the banking domain.This contains 13,o83 customer service queries labeled with 77 intents.It is split into two subsets: train (1o,0o3 examples) and test (3,o80 samples).There are two advantages of this dataset - its a single domain dataset (banking)and has a diverse set of intents, and it has partially overlapping intent categories,which means that the model cannot rely entirely on individual word statistics and semantics and requires some understanding of the task.The dataset details are shown in Table 2.

# 4Methodology

# 4.1 In-Context Learning

For in-context learning, we use open-source LLMs like:

· Llama: We used Meta's Llama-3 8B model[1].Llama-3 has 2 variants at the time of writing - 8B and 7oB parameter models,both of which have a context length of 8,192.   
· Mistral:We used Mistral-7B model[11] version 0.3 which has a context window of 32,768.It has two other variants - ${ 8 } \mathrm { x } 7 \mathrm { B }$ and $8 \mathrm { x } 2 2 \mathrm { B }$ models.   
· Falcon: We used TII's Falcon-7B model [2],which has a context window of 2,048.Falcon has many variants -Falcon 2 (11B),180B,40B,7.5B,1.3B models.   
· Gemma: We used Gemma-2 9B model (Google) [10],which has context length of 8,192.

These pre-trained chat models have been fine-tuned to follow instructions with Reinforcement Learning from Human Preferences (RLHF)[21].Therefore,we use the Instruction-tuned versions of each of the models.Since banking use-cases often have limited resources at disposal,we have selected resource-efficient opensource smaller versions of the models that can easily be run in an infrastructure with upto $2 2 . 5 \ : \mathrm { G B }$ of GPU memory.We experiment with 4-bits quantized versions of each of the models.

# 4.2 Prompt Engineering

Articulate prompt engineering is crucial in steering behaviour and response of the LLMs by providing them the appropriate instructions and context for a task. Our prompt template carries forward the ones used by Loukas et al.(with slight variations).The prompt template is shown below.

"You are an expert assistant in the field of customer service.Your task is to classify the customer's question after <<<>>> into one of the following predefined classes:

activate_my_card   
age_limit

you will be penalized．Do NOT provide explanations or notes.   
<<<   
Question:{dialogue}   
VVV   
Class:""

The prompt starts with an instruction that encompasses the context of the task including a knowledge base detailing the classification criteria and names of the classes.The test statement is then provided as an input by the user.

4.2.1Zero Shot and Random Few Shot Learning.For our initial approach,we experimented with zero-shot learning and in-context learning with 1 and 3 examples per class,chosen randomly from the training set.

4.2.2Using Human Expert Annotated Examples.The Banking77 dataset has several partial class overlaps,as observed by Casanueva et al.Several studies like thatof Ying and Thomas tried to use additional annotations to reduce the overlap,however,such datasets are not publicly available.Loukas etal.were able to curatea subset of the dataset with the help of a subject matter expert (SME).The SME was provided with10 randomly chosen examples,and they selected the top 3 based on their alignment to each of the intents.They showed that in few-shot learning,these expert-selected examples outperformed randomly selected ones.In this way, they demonstrated that their approach reduced class overlaps and ensured only the most relevant examples were chosen for each class.We make use of their openly available curated datasetin this work.

4.2.3Semantically Similar Few Shot Learning.In this approach,we select those examples for in-context learning from the training set, which are semantically similar to the test statement at inference. This is achieved by first training a sentence transformer (MPNet) [23] on the training set,which learns to encode the statements in the embedding space based on whether their class is similar or dissimilar.

MPNet [23] is a transformer-based model which uses permuted language modelling to learn dependency among predicted tokens, unlike BERT which neglects it,as well as uses auxiliary position information as input.On downstream tasks such as GLUE,and SQuAD,it is known to outperform existing state-of-the-art models like BERT,XLNet,and ROBERTa.

In this work, we select one of its variations-'all-mpnet-base-v2', which also ranks among the top in the HuggingFace sentence transformers leaderboard.Therefore,based on this idea,for each test sentence to be classified, we use the all-mpnet-base-v2 vector embeddings and the cosine similarity metric (for distance calculation) to retrieve the 5,10,and 20 most similar examples at inference time while performing in-context learning.

# 6LLMs for Data Generation in Low-Resource Settings

As mentioned earlier, business use-cases in domains like finance (particularly in banking) suffer from scarcity of data because of challenges such as privacy regulations or risk of data leakage, due to which data access is restricted. Therefore,making maximum use of available limited datasets (data-centric AI) is preferred to making use of more complex models (model-centric AI). This becomes more challenging in our case,where we have such a high number of classes (77).

Previous studies [19] have shown that augmenting with artificial examples does give a boost to the performance, however this positive trend only holds until a threshold of added artificial examples is reached.

To generate examples,we simulate a worst-case scenario where only one example per class is available. Thereafter, we prompt our best-performing model (Mistral) with each example and instruct it to generate upto 3 artificial examples to augment the limited dataset.The prompt is shown below:

""You are an excellent assistant at rephrasing sentences Your task is:Given an example of text instance that belongs in a specific label,create 3 similar sentences.

Finally,we use in-context learning using three sets of few-shot examples - two sets constructed by augmenting the one example we have in this scenario with 1 and 2 artificially generated examples respectively,and an additional set which consists of all 3 LLM generated examples.This was done to see how well the data generated by the LLM can supplement the original limited data,as well as how better or worse are they compared to the original data.

Figure 2 shows the $\mu { - } \mathrm { F } 1$ score for the different few-shot settings. Starting from the 1-shot setting with $7 4 . 0 \% \mu$ -F1,when an additional artificial example is added,it provides onlya slight boost to $7 4 . 1 \% \mu -$ F1,as seen in the augmented 1-shot setting with generated example in the ratio 1:1(1 original example $^ { + 1 }$ generated).However, this performance remains comfortably higher than the 2-shot setting with the real data $( 7 3 . 8 \% \mu \mathrm { - } \mathrm { F } 1 ,$ ,indicating that there could be some value in artificially generating data.After this,the performance decreases (see 2 and 3-shot settings).This is likely because the additional generated examples inject more noise into the model than the actual value,as well as they are not substantially different from each other and thus havea low variance to provide the model good enough representative information.As expected, the real data remains superior and much more meaningful as compared to the generated data.

# 7.1 Retrieval-Augmented Generation (RAG)

To understand if a RAG-based approach could help achieve a boost in performance,we conducted experiments on two of our bestperforming LLMs,by retrieving the intent of the sentence whose vector encoding is closest to the test sentence at inference time.For example,whereas in the standard few-shot setting,we provide 231 examples (3 samples $\mathbf { \yen 7 7 }$ classes,in a 3-shot setting); in the case of RAG - the retriever component can only provide five,ten or twenty most similar examples.This results ina significantly reduced set of representative examples,which are relevant for each inference classification.Augmenting in-context learning with relevant examples like these have been used as part of active learning algorithms in worksby Lewis etal.and Liu etal.,where kNN was used to select the examples to be provided in context.In a recent work,Loukas et al.have also used this methodology to reduce the representative examples provided in the context of LLMs to a tiny set.

Therefore.based on this idea,for each inference sentence to be classified,we use the all-mpnet-base-v2 vector embeddings and the cosine similarity metric to retrieve the most similar examples to the inference sentence.Then,we provide - only the 5 $( 2 . 2 \% )$ ,10 $( 4 . 3 \% )$ and 20 $( 8 . 7 \% )$ most similar examples in the prompt context of LLMs, as shown in Figure 1.

The results of this approach, as seen in the three lower groups of Table 4,show significantly improved results in performance. For instance,when we retrieve only five similar instances ( $2 . 2 \%$ of the 231 total examples) for each inference call,Mistral has a 91.17 $\mu { - } \mathrm { F } 1$ Vs. # 9Fine-Tuning of Instruction Tuned LLMs

Based on the performance of models during in-context learning, we select the Mistral-7B model for fine-tuning to investigate if model performance could be enhanced further. Each sample from the training set was converted into a prompt which included the test statement as a user input and the true label as the reply expected from the chat assistant.The prompt template used was exactly the same as depicted in Section 4.2.

Since our focus is on resource efficient models,we experiment with three Parameter Efficient Fine-Tuning (PEFT) approaches - QLoRA(Quantized Low-Rank Adaptation)[7],rsLoRA rank-stablized Low-Rank Adaptation) [12],and DoRA (Weight-Decomposed LowRank Adaption)[18],and used the unsloth library for implementation and inference.

We first quantized the pre-trained model to 4-bit and selected the following modules for fine-tuning:

(1) q_proj (query projection): Part of the attention mechanism, and transforms the input into query vectors that are used to compute attention scores.   
(2) k_proj (key projection): Projects the input into the key space by producing key vectors that are compared with query vectors to determine attention weights.   
(3) V_proj (value projection): Projects the input into the value space in the attention mechanism,by producing value vectors that are weighted by the attention scores and combined to form the output.   
(4) o_proj (output projection): Projects the output of the attention mechanism (combined weighted value vectors) back into the original space with input dimension,integrating attention results into the model.   
(5) gate_proj(gate projection): Gated mechanism which controls the flow of information through the gate,allowing selective information passage based on learned weights.   
(6) up_proj(up projection): Expands the input to a higher-dimensional space,often used in feedforward layers or when transitioning between different layers with differing dimensionalities.   
(7) down_proj (down projection): Compresses the input to a lower-dimensional space,useful for reducing computational complexity and controlling the model size.

# 11 CONCLUSION

We leveraged LLMs for financial intent detection using the Banking77 dataset, which has a large number of intents with overlapping labels.We conducted a comprehensive few-shot text classification study based on random and expert-selected examples using smaller instruction-tuned open-source LLMs (like Mistral and Gemma-2). To showcase how banks can use LLMs in data-scarce scenarios, we also experimented with generating artificial data for data augmentation using LLM, which seemed to help,albeit only slightly. Further, using a RAG-based approach,we demonstrated that such LLMs can out-perform their larger closed-source counterparts (like GPT-4 and Claude-2). Using an ablation study,we found that the significant performance gains of this approach over conventional few-shot learning were most likely due to the retrieval of biased examples.We discussed the trade-offs between cost and performance for these approaches and models. Our results clearly demonstrate the performance effectiveness and cost-efficiency of the RAG approach using smaller open-source LLMs over larger ones.Finally, our experiments with three Parameter-Efficient Fine-Tuning (PEFT) methods- QLoRA,rsLORA and DoRA,showed QLoRA to be the best performing as well as most efficient method.Based on this,we proposed BAI-Fintent LLM, based on fine-tuned Mistral-7B,which surpasses all other approaches in performance on banking intent identification,and at the same time,is most cost efficient as well. In future work, we willinvestigate Chain-of-Thought techniques to mitigate the errors in overlapping class labels.
