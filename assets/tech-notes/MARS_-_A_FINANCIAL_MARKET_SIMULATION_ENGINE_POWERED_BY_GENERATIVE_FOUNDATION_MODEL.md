# MARS: A FINANCIAL MARKET SIMULATION ENGINE POWERED BY GENERATIVE FOUNDATION MODEL

本文提出的方法核心是构建一个基于生成式基础模型的金融市场的高保真仿真引擎——MarS（Market Simulation Engine），其底层由一个专门针对金融市场的订单级生成基础模型——Large Market Model（LMM）驱动。该方法旨在实现金融市场的**高分辨率、可控制性与交互性**三重关键特性，从而为金融预测、风险检测、策略分析和智能体训练等任务提供全新的仿真范式。

### 1. Large Market Model（LMM）：订单级生成基础模型

LMM 是一个专门为金融市场的订单级动态建模而设计的生成式基础模型，其核心思想是将金融市场视为一个由离散订单序列构成的时序系统，并通过结构化建模方式捕捉微观订单行为与宏观市场趋势的耦合关系。

#### 1.1 订单与订单批次的双尺度表征（Tokenization）

LMM 采用双路径建模架构，分别处理两种粒度的市场数据：

- **订单序列模型（Order Model）**：  
  使用**因果Transformer**（causal transformer）对单个订单进行序列建模。每个订单 $ \text{order}_i $ 被编码为一个嵌入向量：  
  $$
  \text{Emb}_i = \text{emb}(\text{order}_i) + \text{linear-proj}(\text{LOB}_i^{\text{volumes}}) + \text{emb}(\text{LOB}_i^{\text{mid-price}})
  $$  
  其中：
  - $\text{order}_i$ 是一个四元组（类型, 价格, 体积, 间隔），类型包括 ["Ask", "Bid", "Cancel"]；
  - $\text{LOB}_i^{\text{volumes}}$ 是买卖盘前10档的订单簿深度（体积）；
  - $\text{LOB}_i^{\text{mid-price}}$ 是盘口中价（以开盘以来的最小价格跳动单位表示）。

  该模型通过自回归方式预测下一个订单的生成，确保订单序列符合真实市场的微观结构（如订单簿的动态演化）。

- **订单批次模型（Order-Batch Model）**：  
  为捕捉宏观市场行为的时间聚合模式，将固定时间窗口（如1分钟）内的订单集合转化为一个**类图像表示**（order image），其结构为：
  - 三维通道（RGB）分别代表：Bid、Ask、Cancel；
  - 横轴表示价格相对于中价的档位（price slot）；
  - 纵轴表示订单体积的分箱（volume slot）；
  - 像素值表示该位置的订单数量。

  该图像通过**VQ-VAE**（Vector Quantized Variational Autoencoder）进行压缩与重建，形成离散的潜在表示，再通过**自回归Transformer**建模订单批次序列的时序依赖，从而捕捉市场波动的宏观模式。

#### 1.2 集成模型（Ensemble Model）

Order Model 与 Order-Batch Model 通过一个**集成框架**协同工作：
- Order Model 提供**细粒度控制**，生成精确到单个订单的动态；
- Order-Batch Model 提供**宏观上下文约束**，确保生成的订单序列符合整体市场趋势；
- 两者通过**自回归机制**联合建模，形成一个多层次、多尺度的生成系统。

#### 1.3 条件生成机制（Conditional Trading Order Generation）

LMM 的生成过程是**条件化**的，生成下一个订单 $x_{i+j+1}$ 依赖于四个关键输入条件：
1. **DES.TEXT**：用户输入的自然语言场景描述（如“价格飙升”或“波动率崩溃”），通过LLM检索历史相似事件，转化为细粒度控制信号；
2. **Interactive Orders**：用户实时注入的订单序列 $(\dot{x}_{i+1}, \dots, \dot{x}_{i+j})$，用于模拟交易策略的即时影响；
3. **Starting Sequence**：初始订单序列 $(x_0, \dots, x_{m-1})$，通常采用最近的真实历史订单，保证仿真起点的真实性；
4. **MTCH.R**：订单匹配规则，模拟真实市场的撮合逻辑（如价格优先、时间优先），确保生成的订单在结构上合法。

生成概率形式为：
$$
p(x_{i+j+1} \mid \{\text{DES.TEXT}, (\dot{x}_{i+1}, \dots, \dot{x}_{i+j}), (x_0, \dots, x_m), \text{MTCH.R}\})
$$

#### 1.4 可扩展性（Scaling Law）

LMM 在数据规模与模型参数量上均表现出显著的**缩放规律**（scaling law）：
- Order Model 在320亿token上训练，参数从2M至1.02B；
- Order-Batch Model 在100亿token上训练，参数从150M至3B；
- 实验表明，随着数据量和模型规模增大，模型的预测性能（如验证损失）持续提升，符合生成式基础模型的通用缩放趋势，证明其具备处理超大规模金融数据的潜力。

### 2. MarS：基于LMM的金融仿真引擎

MarS 是一个集成LMM与**模拟撮合引擎**（simulated clearing house）的端到端仿真系统，其核心创新在于**实时交互式订单生成与市场反馈闭环**。

#### 2.1 模拟撮合引擎（Simulated Clearing House）

- 每生成一个订单 $x_i$，MarS 将其与用户注入的交互订单 $(\dot{x}_{i+1}, \dots, \dot{x}_{i+j})$ 一起输入模拟撮合引擎；
- 撮合引擎依据真实市场的匹配规则（MTCH.R）执行撮合，更新订单簿（LOB）状态；
- 更新后的LOB和撮合结果作为新输入，反馈给LMM，用于生成下一个订单 $x_{i+j+1}$；
- 此过程形成**动态闭环**：用户动作 → 市场响应 → 生成新订单 → 再响应 → 持续演化。

#### 2.2 双重生成控制原则

为实现**可控性与真实性的平衡**，MarS 遵循两大设计原则：

1. **“基于已实现现实塑造未来”（Shaping the Future Based on Realized Realities）**：  
   每个时间步的订单批次生成，必须基于当前真实撮合结果（包括用户注入订单的即时市场影响），确保生成行为反映实际市场反馈。

2. **“从所有可能未来中择优”（Electing the Best from Every Possible Future）**：  
   在每个时间步，LMM 生成多个可能的订单批次分布，通过**控制信号过滤器**（由DES.TEXT或历史回放曲线生成）选择最匹配目标场景的分布，作为下一阶段订单生成的条件，确保可控性不牺牲真实性。

#### 2.3 生成流程（图4）

- **订单批次层**：Order-Batch Model 生成 N 个可能的下一分钟订单批次分布；
- **控制信号过滤**：根据 DES.TEXT 或回放曲线，筛选出最优分布（标记为 ★）；
- **订单层**：Order Model 在该最优分布的约束下，生成具体的订单序列；
- **集成模型**：融合订单级响应与批次级约束，生成最终订单序列；
- **反馈循环**：生成的订单被送回撮合引擎，更新LOB，用于下一轮预测，形成持续动态仿真。

### 总结：方法核心贡献

- **LMM**：首个面向金融市场的订单级生成基础模型，采用双尺度（订单+订单批次）建模 + 集成架构，实现微观行为与宏观趋势的联合建模；
- **MarS**：首个支持**交互注入、条件控制、实时反馈**的金融仿真引擎，通过模拟撮合引擎构建闭环仿真；
- **条件生成框架**：统一将金融任务（预测、检测、分析、训练）转化为“基于历史、用户输入与市场规则的订单生成”问题；
- **可扩展性**：验证了LMM在数据与模型规模上的缩放规律，为未来更大规模金融仿真奠定基础。

该方法首次将生成式基础模型的范式系统性引入金融领域，突破传统统计模型或代理模型在分辨率、交互性与可控性上的局限，为金融AI开辟了“仿真即平台”的新范式。
